Expectations, in place

Every point-set method of this package, Unscented, GaussHermiteCubature, GaussLaguerreQuadrature and the generalized unscented transform, approximates an expectation the same way: it places weighted points $x_i$ for a measure, and

\[\mathrm{E}[f(x)] ≈ \sum_i w_i f(x_i).\]

The measure is given by plain parameters, never by a distribution: (m, V) for a normal, a number and a variance or a vector and a covariance matrix; (means, covs), tuples with one entry per independent normal input; (shape, scale) for a gamma; (m, V, S, K) for the generalized unscented transform's higher moments. Everything else is that sum, written once for every method:

functionreturns
expectation(method, f, params...)$\sum_i w_i f(x_i)$
approximate(method, f, params...)the mean and covariance of $f(x)$
forward_statistics(method, f, params...)those and the cross-covariance of $x$ and $f(x)$, which smoothRTS takes
approximate_meancov(method, g, params...)the mean and covariance of the measure reweighted by $g$

A moment, a cross-covariance, the moments of a reweighted measure: each is an expectation of a transformed function, so no method needs its own.

using MessagePassingRulesApproximations

f(x) = sin(x) + x^2
m, v = 0.5, 0.3

(
    unscented = approximate(Unscented(), f, m, v),
    cubature = approximate(ghcubature(20), f, m, v),
    E = expectation(ghcubature(20), f, m, v),
)
(unscented = (0.9575117095373571, 1.1616414363197691), cubature = (0.9626453851785196, 1.0403909071186657), E = 0.9626453851785196)

Log space

A LogIntegrand gives a function by its logarithm. expectation then returns the logarithm of the expectation, and approximate_meancov the moments of the measure reweighted by a function that would underflow everywhere, as a sharp likelihood far from the prior does:

sharp(x) = -(x - 30)^2 / 2e-3   # the log of a likelihood far from N(0, 1)

(
    direct = approximate_meancov(ghcubature(20), x -> exp(sharp(x)), 0.0, 1.0),
    log_space = approximate_meancov(ghcubature(20), LogIntegrand(sharp), 0.0, 1.0),
)
(direct = (NaN, NaN), log_space = (7.619048541679759, 0.0))

In place, with nothing allocated

Every operation op(method, f, params...) has an in-place form,

op!(out..., ws, method, f, params...)

with three rules:

  1. Outputs first. The leading out... are the array-valued parts of the result, in order, written in place; the scalar parts are returned. A scalar result has no out: approximate!(ws, method, f, m, v) returns two numbers, approximate!(m, V, ws, method, f, μ, Σ) writes a vector and a matrix.
  2. One workspace, workspace(method, f, params...), with the arguments of the operation it serves. It holds every buffer the operation needs, built once; it calls f once to learn the size of its output. Then any number of calls, with parameters of other values and the same shapes, allocate nothing of their own. What f itself allocates is its own business: a function that returns a static vector allocates nothing.
  3. The allocating form calls the in-place one. op(method, f, params...) builds the workspace and the outputs and calls the same code, evaluating f once per point.
import MessagePassingRulesApproximations: workspace

gh = ghcubature(10)
ws = workspace(gh, f, m, v)
approximate!(ws, gh, f, 0.1, 0.2)   # compile
@allocated approximate!(ws, gh, f, 0.1, 0.2)
0

The same in three dimensions, with a vector output written into μ and Σ:

g(x) = [x[1] * x[2], sin(x[3])]
μ_in, Σ_in = [0.1, 0.2, 0.3], [1.0 0.1 0.0; 0.1 1.0 0.1; 0.0 0.1 1.0]
ut = Unscented()
ws = workspace(ut, g, μ_in, Σ_in)
μ, Σ = zeros(2), zeros(2, 2)
approximate!(μ, Σ, ws, ut, g, μ_in, Σ_in)   # compile
g(μ_in)
(call = @allocated(approximate!(μ, Σ, ws, ut, g, μ_in, Σ_in)), by_g = 7 * @allocated(g(μ_in)))
(call = 560, by_g = 560)

What the call allocates is g's: a new vector at each of the seven sigma points. A function that returns a static vector, from StaticArrays, or a number, allocates nothing, and the call then allocates nothing at all.

Linearization keeps its ForwardDiff configuration in its workspace, and smoothRTS! its factorisation.

A workspace as a rule's scratch

A workspace suits the scratch of a MessagePassingRulesBase rule (see scratch): it is written before it is read on every call, so a workspace reused, or filled with garbage, gives the same result as a fresh one; no result points into it; and its type follows from the types of the inputs, so an engine infers it. A rule declares it from its inputs and calls the in-place form in its body:

@define_message_update_rule(
    node = DeltaFn, target = :out, algorithm = DeltaApproximation{<:Unscented},
    args = (m[:in...]::NormalDistributionsFamily,),
    scratch = (algo, ctx, args) -> workspace(algo.method, f, means(args), covs(args)),
    body = (scratch, algo, ctx, args) -> begin
        m, V = approximate!(scratch, algo.method, f, means(args), covs(args))
        NormalMeanVariance(m, V)
    end,
)

Adding a method

A method becomes a point-set method, with every operation above and their in-place forms, by implementing these functions for its point set, a type of its own:

  • pointset(method, params...): the point set, its buffers allocated for parameters of these shapes;
  • prepare!(points, method, params...): places the points, writing every buffer it reads;
  • npoints, point!, weight and center, and optionally covweight, logweight and weightsign;
  • is_value, for a point set that is an immutable value, which prepare! returns anew.

A method that defines only getpoints and getweights for a normal still works with every operation, collecting its points on each call, which allocates.

API

MessagePassingRulesApproximations.expectation — Function
expectation(method, f, params...)
expectation!(ws, method, f, params...)
expectation!(out, ws, method, f, params...)

The expectation E[f(x)] ≈ Σᵢ wᵢ f(xᵢ) of f under the measure of params, by the point set method places for it.

Arguments

  • method: a point-set method, such as Unscented, GaussHermiteCubature or GaussLaguerreQuadrature;
  • f: a function of one point, returning a number or a vector; with several inputs, a function of one argument per input. A LogIntegrand gives the logarithm of the expectation, computed in log space;
  • params: the measure's parameters, as method takes them: (m, V) for a normal, a mean and a variance or a vector and a covariance matrix; (means, covs), tuples with one entry per independent normal input; (shape, scale) for the gamma of Gauss–Laguerre quadrature.

The in-place forms work in a workspace(method, f, params...), and allocate nothing of their own: expectation!(ws, …) for a scalar f, expectation!(out, ws, …) for a vector one, writing the result into out.

Examples

julia> expectation(ghcubature(3), x -> x^2, 1.0, 4.0) ≈ 5.0  # E[x²] = m² + v
true

julia> exp(expectation(ghcubature(20), LogIntegrand(x -> x), 0.0, 1.0)) ≈ exp(0.5)  # E[eˣ]
true

MessagePassingRulesApproximations.approximate — Method
approximate(method, f, params...) -> (m, V)
approximate!(ws, method, f, params...) -> (m, V)
approximate!(m, V, ws, method, f, params...) -> (m, V)

The mean m and variance, or covariance, V of f(x) under the measure of params, by the point set of method: m = Σᵢ wᵢ f(xᵢ) and V = Σᵢ w⁽ᶜ⁾ᵢ (f(xᵢ) - m)(f(xᵢ) - m)'. The arguments are expectation's.

The in-place forms work in a workspace(method, f, params...) and allocate nothing of their own: approximate!(ws, …) for a scalar f, approximate!(m, V, ws, …) for a vector one, writing into the vector m and the matrix V.

Linearization has an approximate of its own, which returns the local linear map.

Examples

julia> m, V = approximate(ghcubature(10), x -> 2x + 1, 1.0, 0.5);

julia> m ≈ 3.0 && V ≈ 2.0
true
source

MessagePassingRulesApproximations.forward_statistics — Method
forward_statistics(method, f, params...) -> (m, V, C)
forward_statistics!(…, ws, method, f, params...) -> (m, V, C)

The mean m and covariance V of f(x), as approximate computes them, and the cross-covariance C = Σᵢ w⁽ᶜ⁾ᵢ (xᵢ - x̄)(f(xᵢ) - m)' between the input x, its several inputs concatenated into one vector, and f(x): the forward statistics smoothRTS takes. C is a number for a scalar input and scalar f, a vector for a vector input and scalar f, a row 1 × length(f(x)) for a scalar input and vector f, and a matrix otherwise.

The in-place form works in a workspace(method, f, params...), allocates nothing of its own, and takes the array-valued parts of the result first, in order: forward_statistics!(ws, …) when all three are scalars, forward_statistics!(C, ws, …) for a vector input and scalar f, and forward_statistics!(m, V, C, ws, …) for a vector f.

Examples

julia> m, V, C = forward_statistics(ghcubature(10), x -> 2x + 1, 1.0, 0.5);

julia> m ≈ 3.0 && V ≈ 2.0 && C ≈ 1.0   # C = Cov(x, 2x + 1) = 2 × 0.5
true

forward_statistics!(C, ws, method, f, params...) -> (m, V, C)

The in-place form of forward_statistics, in a workspace, with the array-valued parts of the result first: none when all three are scalars, C for a vector input and a scalar f, and m, V and C for a vector f. It allocates nothing of its own.

MessagePassingRulesApproximations.LogIntegrand — Type
LogIntegrand(logf)

A function given by its logarithm, logf(x) = log f(x), for computations in log space that a direct f would underflow or overflow. Called, it returns exp(logf(x)).

  • expectation(method, LogIntegrand(logf), params...) returns log E[f(x)]: log in, log out.
  • approximate_meancov(method, LogIntegrand(logg), params...) returns the moments of the measure reweighted by g, accurately however small g is over it.

Examples

julia> sharp = LogIntegrand(x -> -1e4 * (x - 3)^2);   # exp(-1e4 (x - 3)²) underflows away from 3

julia> m, v = approximate_meancov(ghcubature(40), sharp, 0.0, 1.0);

julia> isfinite(m) && isfinite(v)
true

MessagePassingRulesApproximations.AbstractWorkspace — Type
AbstractWorkspace

The supertype of the workspaces workspace builds: the memory an in-place operation, such as approximate! or expectation!, works in. A workspace is written before it is read on every call, so one workspace serves any number of calls, with any parameters of the shapes it was built for; it never holds a result.

source
MessagePassingRulesApproximations.workspace — Function
workspace(method, f, params...) -> AbstractWorkspace

The memory the in-place operations of method need for the function f and parameters of the shapes of params: its points, factors and the values of f at the points. It takes the arguments of the operation it serves, and calls f once, at the first point, to learn the size and type of its output.

Build it once and pass it to every call of an in-place operation, such as approximate!, forward_statistics!, expectation! or approximate_meancov!: those calls then allocate nothing of their own. Parameters of other values but the same shapes and types may be passed to each call. It can serve as a rule's scratch: it is written before it is read on every call, and no result points into it.

Examples

julia> import MessagePassingRulesApproximations: workspace

julia> ws = workspace(Unscented(), sin, (0.0,), (1.0,));

julia> m, V = approximate!(ws, Unscented(), sin, (0.5,), (0.1,));

julia> m ≈ first(approximate(Unscented(), sin, (0.5,), (0.1,)))
true

MessagePassingRulesApproximations.pointset — Function
pointset(method, params...)

The point set of method for parameters of the shapes of params, with its buffers allocated and its points not yet placed: prepare! places them. A method that implements it, prepare!, npoints, point!, weight and center gets every generic operation, expectation, approximate, forward_statistics and approximate_meancov, with their in-place variants.

source
MessagePassingRulesApproximations.prepare! — Function
prepare!(points, method, params...) -> points

Places the points of points for the parameters params of method's measure: factorises the covariance, computes the weights. It writes every buffer it reads, so a point set prepared for other parameters, or never prepared, gives the same result. It returns the prepared point set: points itself when it is mutable, a new value when it is an immutable one, as a scalar point set of a few numbers is, so that it lives on the stack. Callers use the result.

MessagePassingRulesApproximations.weight — Function
weight(points, i)

The weight of the i-th point of points in an expectation: the weights sum to one, and E[f(x)] ≈ Σᵢ weight(points, i) f(point!(points, i)). Some may be negative, as the centre's is in the unscented transform.

source
MessagePassingRulesApproximations.covweight — Function
covweight(points, i)

The weight of the i-th point of points in a covariance. It is weight for every method but the unscented transform, whose centre weighs differently in a covariance.

source
MessagePassingRulesApproximations.logweight — Function
logweight(points, i)

The logarithm of the absolute value of the weight of the i-th point of points, for an expectation computed in log space, LogIntegrand: log(abs(weight(points, i))) unless the method has it more accurately, as Gauss–Hermite does for weights that underflow. The sign is weightsign's.

source
MessagePassingRulesApproximations.weightsign — Function
weightsign(points, i)

The sign of the weight of the i-th point of points, 1 or -1, for an expectation computed in log space. The weights of a quadrature are positive; the unscented transform's centre may weigh negatively.

source
MessagePassingRulesApproximations.center — Function
center(points)

The centre of the point set points, the mean of its measure: a number or a vector, one buffer of points. The cross-covariance of forward_statistics is taken around it.

source
MessagePassingRulesApproximations.is_value — Function
is_value(points) -> Bool

Whether the point set points is a plain, immutable value, which prepare! returns anew rather than writes into, as the scalar point sets of the unscented transform and of Gauss–Hermite cubature are: they then live on the stack in the allocating operations, and a workspace holds them in a mutable holder. false by default; a method whose point set is immutable returns true, and its pointset returns the point set already prepared for the parameters it is given.
